# 루미 기능 점검 현황 (2026-10-19)

영상 촬영 전에 실제 앱을 VS Code에서 실행해 기능을 하나씩 눌러 본 기록이에요. 다른 PC에서 같은 점검을 이어서 할 수 있도록 정리했어요.

- 기준 커밋: `400e6ff` (오늘 작업은 그 위에 한 커밋으로 올라가요)
- 점검한 PC: Windows 11, Intel Arc 내장 그래픽(Vulkan), RAM 16GB, Python 3.14.3, Ollama 0.30.10, llama3.1 8B
- 자동 테스트: `python -m pytest -q` → **3,232개 통과**, 5개 건너뜀 (오늘 시작 시 3,190개)

## 1. 가장 중요한 문제: Ollama 엔진이 죽어요

AI 답변 중 **"⚠️ AI 모델 서버에서 오류가 발생했습니다"**가 나오고, 화면에 **"llama-server.exe - 응용 프로그램 오류 (0xe06d7363)"** 창이 떠요.

### 지금까지 확인한 것

| 확인 | 결과 |
|---|---|
| 순수 글 약 3,000토큰 | 9번 중 9번 성공 |
| 순수 글 약 4,000토큰 | 4번 중 3번 성공 |
| 순수 글 약 6,000토큰 | 3번 중 3번 실패 |
| 정해진 토큰 한계? | 아니에요. 문맥 한도(8,192)보다 훨씬 작은 요청에서도 죽어요 |
| 메모리 부족? | 아닌 것 같아요. 남은 메모리 9.7GB일 때도 죽었고, Windows 메모리 부족 기록이 없어요 |
| CPU로만 실행 | 못 했어요. 모델 올릴 메모리가 부족해 로딩 실패 |
| 오후 들어서는 | 작은 요청(약 3,000토큰)도 연속으로 죽었어요 |

- 죽는 곳은 루미 코드가 아니라 Ollama 내부 엔진(llama-server)이에요. Intel Arc + Vulkan 조합의 Ollama 결함일 가능성이 높아요.
- 엔진이 죽으면 Windows 오류 창이 뜨고, **그 창을 닫을 때까지 루미가 최대 5분 멈춰요.** [확인]을 눌러 주세요.
- Ollama 0.40.6 업데이트가 나와 있어요(아직 안 해 봄).

### 다른 PC에서 할 실험 (같은 방법으로 비교)

프로젝트 폴더에서:

```
ollama --version
python scripts/ollama_engine_probe.py size 3000 5
python scripts/ollama_engine_probe.py size 4000 3
python scripts/ollama_engine_probe.py size 6000 3
python scripts/ollama_engine_probe.py lumi "매일 알림 취소해줘"
python scripts/ollama_engine_probe.py lumi "오늘 앱 사용 시간 알려줘"
python scripts/ollama_engine_probe.py lumi "대용량 파일 찾아줘"
```

같이 적어 둘 것: 그래픽카드 이름(작업 관리자 > 성능 > GPU), RAM, Ollama 버전, `ollama ps`의 PROCESSOR 칸(GPU/CPU).

판단 기준:
- **다른 PC에서는 6,000토큰도 성공** → 이 노트북(Intel Arc)의 엔진 문제. 이 노트북은 Ollama 업데이트를 시험.
- **다른 PC에서도 실패** → 요청 크기를 더 줄여야 함(아래 2-④의 상한 3,500을 더 낮추기 등).
- 이 노트북에서 Ollama를 0.40.6으로 올린 뒤 같은 실험을 다시 돌려 숫자로 비교.

## 3. 기능 점검 현황

### ✅ 실제 앱에서 정상 확인
- 로그인, 자동 로그인, 홈 화면 위젯(시스템 상태·날씨·일정·할 일·세션)
- 일반 대화, 대답 멈추기
- 할 일 추가, 메모 저장, 가계부("커피 4500원에 샀어"), 날씨
- 컴퓨터 상태, 시작프로그램 부팅 영향 분석, "어제보다 느려졌어?"(기록 없으면 없다고 답함)
- 종합 보안 점검("내 PC 안전해?")
- 타이머 설정·목록·취소, 매일 알림 설정·목록·취소
- 다나와 최저가 검색(상품 카드·[보기] 버튼)
- 요약, 번역, 메일 초안
- 파일 자연어 검색("지난주에 받은 PDF")
- 활동 이력("아까 나한테 뭐 해줬어?")
- 화면: 대화 기록, 마켓, 캘린더, 스킬, 환경설정(다크 모드)

### ⚠️ 되긴 하지만 손볼 점
- **활동 이력**: AI가 문장으로 정리하지 못해 `search_files` 같은 내부 이름이 그대로 보임
- **가계부**: "커피 4500원 지출 기록해줘"는 금액을 다시 물음 → 영상에서는 **"커피 4500원에 샀어"**
- **구글 캘린더 일정 등록**: 캘린더 화면의 **[구글 연동하기]**로 먼저 연결해야 함. 연결 후 실제 등록은 아직 확인 못 함

### ❌ 엔진 오류로 판단 못 함 (엔진 해결 후 다시)
- 오늘 앱 사용 시간
- 대용량 파일 찾기
- 실시간 감시 상태

### ⏳ 아직 안 한 것
- 데이터 백업
- 내부 캘린더(구글 없이)
- 파일 위치 열기
- 회원가입·아이디 찾기·로그아웃·마이페이지
- 위젯 설정, 자동 업데이트
- 구글 캘린더 연결 후 일정 등록

### 🚫 일부러 안 한 것 / 할 수 없는 것
- PC 정리·최적화(임시 파일 삭제), 프로그램 종료, 방화벽 차단 → 실제로 시스템을 바꿔서 실행 안 함
- 음성 대화(마이크 + 약 200MB 설치), 화면 보고 작업하기(6GB 모델), IoT(스마트 플러그 필요)

## 4. 다른 PC에서 시작하는 법

1. `git pull` 후 VS Code에서 프로젝트 폴더 열기
2. 인터프리터를 **Python 3.11 이상**으로(오늘 PC에서 conda `ai_agent`는 3.10이라 안 됨)
3. `ollama list`에 `llama3.1` 있는지 확인 (없으면 `ollama pull llama3.1`)
4. `auth/email_config.py` 있는지 확인 (없으면 팀에서 받아 넣기)
5. `python -m pytest -q` → 3,232개 통과 확인
6. 위 1번 엔진 실험 먼저 → 결과 기록
7. `app_main.py` 열고 ▶ 실행 → 3번의 ❌·⏳ 항목부터 점검

점검할 때 팁:
- 메모리가 90% 넘으면 답변이 질문마다 30초~1분 걸려요. 안 쓰는 프로그램을 닫고 시작하세요.
- 첫 질문은 모델을 올리느라 더 느려요. 촬영 전에 한 번 대화해 두세요.
- "화면 인식 모델 설치" 창이 뜨면 **[아니요]**. (6GB 다운로드가 시작돼요)
- 오류 창(llama-server.exe)이 뜨면 [확인]을 눌러야 루미가 다시 움직여요.
