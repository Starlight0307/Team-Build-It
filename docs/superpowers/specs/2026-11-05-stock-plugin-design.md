# 루미 주식 플러그인 설계

작성일: 2026-11-05 · 상태: 검토 중

표시 안내: **[요청]** 사용자가 직접 정한 것, **[판단]** 작성자가 정한 기본값(사용자가 바꿀 수 있음)

## 왜 만드나

루미 사용자가 자기 증권 계좌를 연결하면, 증권사 앱을 열지 않아도 루미에게 물어 이익과 손실을 브리핑받고, 대시보드에서 보유 종목과 손익을 보고, 대화로 주문까지 준비할 수 있게 한다. **[요청]**

요청자 본인은 지금 주식을 보유하고 있지 않다. 이 기능은 루미 사용자 전체를 위한 것이며, 개발과 검증은 모의투자 계좌로 한다. **[요청·판단]**

## 목표

1. 증권사 계좌를 연결해 보유 종목, 평균 단가, 평가금액, 평가손익, 수익률을 읽어 온다. **[요청]**
2. 대화(음성 포함)로 손익을 브리핑한다. 예: "오늘 평가손익은 +12만 원이고, 삼성전자가 가장 많이 올랐어요." **[요청]**
3. 홈 대시보드 위젯에 총 평가손익과 보유 종목별 손익을 보여 준다. **[요청]**
4. 매수·매도 주문을 할 수 있게 한다. 단, 아래 "주문 규칙"을 따른다. **[요청]**
5. 사용자가 켜고 끌 수 있는 자동매매를 제공한다. **[요청]**
6. 단계적으로 시세, 체결 내역, 주문 내역과 취소, 다른 증권사까지 넓혀 "주식에 대한 모든 기능"에 가까워지게 한다. **[요청]**

## 하지 않는 것

- 매수·매도 추천, 목표가, 전망, 종목 평가 **[요청]**. "뭘 살까?", "지금 팔까?" 같은 질문에는 추천할 수 없다고 답하고, 사실 정보(보유 현황, 손익, 현재가)만 알려 준다.
- AI가 판단하는 자동매매 **[판단]**. 자동매매는 사용자가 직접 정한 규칙만 실행한다.
- 첫 버전의 해외주식 **[판단]**. 국내주식(원화)부터 한다. 한국투자증권은 해외 잔고가 별도 API이고 환율 계산이 추가된다.
- 시장가, 장전·장후 시간외 주문 **[판단]**. 정규장 지정가만 지원한다. 시장가는 예상 금액이 확정되지 않아 한도와 금액 재확인을 적용할 수 없다.
- 첫 버전의 사용자당 여러 계좌 연결 **[판단]**. 계좌는 하나만 연결하고, 바꾸려면 연결을 해제한 뒤 다시 등록한다. 모의와 실전을 동시에 두지 않아 혼동과 합산 문제를 없앤다. 저장 파일은 나중에 계좌 목록으로 옮길 수 있게 버전 값을 둔다.
- 첫 버전의 정해진 시간 자동 브리핑 **[판단]**. 사용자가 물어볼 때와 빠른 실행 버튼으로만 브리핑한다.
- 마이데이터 방식의 통합 조회. 금융위원회 허가(최소 자본금 5억 원 등)가 필요하다.
- 증권사 웹사이트 자동 조작이나 로그인 정보 수집

## 실패로 보는 경우

기능이 동작해도 다음 중 하나라도 해당하면 실패다.

- 사용자가 직접 켠 자동매매 규칙이 아닌데, 사용자가 확정하지 않은 주문이 나간다.
- 사용자가 자동매매를 껐는데 주문이 새로 나간다.
- 모의 계좌인 줄 알았는데 실제 계좌로 주문이 나간다. 또는 그 반대인데 화면에서 구분되지 않는다.
- 앱 키, 시크릿, 접근 토큰, 계좌번호 전체가 AI 프롬프트, 대화 기록, 로그, 서버 동기화, 백업 파일에 남는다.
- 오래된 시세나 조회 실패를 현재 손익처럼 보여 준다.
- 루미가 매수·매도를 권하는 것처럼 말한다.

## 주문 규칙

**[요청]** AI는 주문 창을 채우기만 하고, 사람이 직접 눌러 확정한다.

- AI가 쓸 수 있는 주문 도구는 "주문 창 열기"뿐이다. AI 도구로 주문 API를 호출할 수 있는 경로를 만들지 않는다.
- 주문 창은 종목명, 종목코드, 매수/매도, 수량, 가격, 예상 금액, 대상 계좌, **모의/실전**을 보여 주고, 사용자가 고칠 수 있다.
- 확정은 마우스 또는 키보드로 그 창의 버튼을 직접 눌러야 한다. 음성으로 확정하는 기능은 없다.
- 기본 포커스는 취소에 둔다. 종목명과 종목코드가 일치하지 않거나, 수량이 0 이하이거나 정수가 아니면 확정 버튼을 비활성화한다.
- 종목 확인과 현재가 표시는 증권사 조회 API로 한다. 이 때문에 시세와 종목 조회는 확장 단계가 아니라 2단계에 포함한다. **[판단]** 확인에 실패하면 확정할 수 없다.

**[판단]** 추가 안전장치:

- 주문 기능은 기본적으로 꺼져 있고, 환경설정에서 따로 켜야 한다. 처음 켤 때 위험 안내에 동의하게 한다.
- 사용자가 정한 1회 주문 금액 한도를 넘으면 확정할 수 없다. 기본값은 100만 원이다.
- 실전 주문은 확정 전에 계좌 비밀번호가 아니라 루미 안의 재확인(예상 금액 다시 입력)을 한 번 더 거친다.
- 같은 내용의 주문을 두 번 누르거나 응답 지연 중 다시 누르는 것을 막는다. 응답이 불분명하면 자동 재시도하지 않고, 체결 내역을 확인하라고 안내한다.
- 주문 결과(시각, 종목, 수량, 가격, 모의/실전, 결과)는 이 사용자의 로컬 기록에 남기고, 기존 활동 이력(`plugins/activity_log.py`)에서 볼 수 있게 한다.

## 자동매매

**[요청]** 자동매매 기능을 넣고, 사용자가 직접 켜고 끌 수 있게 한다.

**[요청]** 규칙 형식은 "삼성전자가 7만 원이 되면 10주 팔아줘"처럼 종목, 가격 조건, 매수/매도, 수량으로 정한다.

아래는 모두 **[판단]**이다.

- **규칙 실행:** 매도는 현재가가 기준가 이상일 때, 매수는 이하일 때 조건 충족으로 본다. 기준가를 지정가로 정규장에 한 번 주문하고, 그 규칙은 끝난다. 반복 실행은 하지 않는다.

- **판단 주체:** 사용자가 정한 규칙만 실행한다. AI는 규칙을 만들거나, 켜거나, 고치거나, 종목을 고르지 않는다. 대화로 끄는 것은 허용하고, 켜는 것은 환경설정에서 직접 눌러야 한다.
- **주문 창과의 관계:** 대화로 내는 주문은 "주문 규칙"을 그대로 따른다. 자동매매만 사람의 확정 없이 주문하며, 이는 사용자가 규칙을 확인하고 켜는 행위를 사전 승인으로 본다.
- **기본값과 즉시 중지:** 기본은 꺼짐이다. 대시보드에 켜짐 상태를 항상 표시하고, 한 번에 전부 멈추는 중지 버튼을 둔다. 중지하면 새 주문을 내지 않으며, 이미 나간 미체결 주문의 처리 방법을 함께 보여 준다.
- **한도:** 1회 주문 금액, 하루 총 주문 금액, 하루 주문 횟수 한도를 필수로 정해야 켤 수 있다.
- **자동 정지:** 한도 도달, 조회·주문 오류, 토큰 만료, 시세 지연, 결과가 불분명한 주문이 생기면 재시도하지 않고 멈춘 뒤 사용자에게 알린다. 다시 켜는 것은 사용자가 한다.
- **재시작:** 앱을 다시 켜도 자동으로 재개하지 않고, 꺼진 상태로 시작해 사용자에게 알린다. 같은 규칙이 두 번 실행되지 않게 실행 기록을 저장한다.
- **한계 고지:** 루미가 켜져 있고 PC가 깨어 있으며 인터넷이 연결돼 있을 때만 동작한다. 컴퓨터가 꺼지면 조건에 도달해도 주문이 나가지 않으며, 수익을 보장하지 않는다는 점을 켤 때 알린다.
- **기록:** 규칙 변경, 켜기·끄기, 실행과 건너뛴 이유를 모두 로컬 기록에 남긴다. 주문이 나가면 알림을 보낸다.

## 실거래 결정 (2026-11-05)

**[요청]** 모의가 아니라 실제 거래가 가능해야 하며, 이미 가진 계좌를 연결해 쓴다. 공개 API가 있는 증권사만 해당한다. 카카오페이증권은 공개 API를 찾지 못해 주문 대상이 아니다.

**[판단]** 실전은 연결할 때 직접 고른다. 주문마다 예상 금액을 다시 입력하고, 실전 자동매매는 켤 때마다 위험 안내에 동의한다. 실제 계좌로 소액 시험과 약관·법 확인을 하기 전에는 `main`에 올리지 않는다. 아래 "공개 범위 결정"의 모의 전용 항목은 이 결정으로 바뀌었다.

## 공개 범위 결정

사용자가 2026-11-05 "코딩해줘"로 진행을 지시했고, 아래 3가지는 답이 없어 작성자의 추천을 적용했다. **[판단]**

- 이번 구현은 모의 계좌 전용이다. 실제 계좌 연결은 보유 종목이 있는 시험자의 확인 뒤에 연다.
- 실제 계좌 조회도 공개 전에 증권사에 문의한다.
- 보유 종목과 손익은 대화 기록에 남을 수 있으며, 계좌를 연결할 때 이를 알린다. 키와 토큰은 남기지 않는다.

## 단계

각 단계는 따로 출시할 수 있어야 한다.

1. **조회와 브리핑:** 한국투자증권 국내주식, 계좌 연결, 잔고 조회, 브리핑, 대시보드 위젯. 브리핑의 현재가는 보유 종목만 다룬다.
2. **모의투자 주문:** 종목 확인, 현재가 조회, 주문 창과 주문 규칙 전체를 모의 계좌에서만 동작시킨다.
3. **모의투자 자동매매:** 규칙, 한도, 중지, 자동 정지를 모의 계좌에서만 동작시킨다.
4. **실계좌 주문:** 2단계가 안정된 뒤 공개한다. **공개 전 조건:** 증권사 약관과 관련 법 검토, 증권사 문의. 이 조건이 해결되지 않으면 공개하지 않는다.
5. **실계좌 자동매매:** 3·4단계가 안정된 뒤 공개한다. 공개 전 조건은 4단계와 같으며, 자동매매 기능 자체에 대한 검토를 따로 받는다.
6. **확장:** 해외주식, 체결 내역, 미체결 취소, 키움·토스 등 다른 증권사. 증권사별 공개 범위를 그때 다시 확인한다.

## 기존 구조에 맞추기

- **플러그인:** `plugins/stock_portfolio.py` **[판단: 이름]**. `core/plugins_registry.py`의 `AVAILABLE_PLUGINS`, `PLUGIN_PILLS`, 기능 소개에 등록한다. 기본 내장이 아니라 마켓에서 설치하는 플러그인으로 둔다. **[판단]**
- **도구 함수:** 다른 플러그인처럼 AI가 부르는 함수로 만든다. 지출 플러그인(`plugins/expense_tracker.py`)처럼 로그인 사용자만 쓸 수 있고, 비로그인이면 안내 문장만 돌려준다. **[판단]**
- **저장:** `data.storage_location.user_data_dir(...)` 아래 사용자별 파일에 `data.secure_store.secure_open`으로 암호화해 저장한다.
- **대시보드:** `widget/iot_panel.py`의 `IotPanel`과 같은 방식으로 `Panel`을 상속해 만든다. `app_main.py`의 `DASHBOARD_WIDGETS`와 `panel_by_id`에 등록하고, 플러그인이 설치됐을 때만 보이게 한다. 네트워크 호출은 화면 스레드 밖에서 한다.
- **주문 창:** `widget/lumi_dialog.py`의 공통 디자인을 쓴 전용 창. `core/ai_worker.py`의 `confirm_required` 신호처럼 작업 스레드에서 화면으로 요청을 넘기되, 창의 확정 버튼 처리만 주문 API를 호출한다.
- **테스트:** `tests/unit`에 네트워크 없이 도는 테스트를 추가한다. 앱의 자동 Release가 이 테스트를 통과해야 공개되므로, 실제 증권사 호출에 의존하면 안 된다.

## 증권사 연결: 한국투자증권

**[판단]** 첫 대상이다. 개인용 REST API와 모의투자 환경이 있다고 확인된 자료가 있다.

- 사용자가 KIS Developers에서 직접 앱 키와 시크릿을 발급받아 루미에 입력한다. 루미가 모든 사용자를 대신하는 공용 키는 쓰지 않는다.
- 모의와 실전은 앱 키, 토큰, 접속 주소가 서로 다르다는 자료가 있으므로, 계좌를 등록할 때 모의/실전을 명시적으로 고르게 하고 섞이지 못하게 한다.
- 증권사별 코드는 한 파일 또는 작은 어댑터에 모아, 나중에 다른 증권사를 붙일 때 플러그인 전체를 고치지 않게 한다. 그러나 다른 증권사를 붙이기 전까지 범용 추상화를 미리 만들지는 않는다.

아래는 **블로그 자료 기준의 미확인 값**이다. 구현 전에 공식 포털(apiportal.koreainvestment.com)과 공식 예제 저장소(koreainvestment/open-trading-api)에서 반드시 대조한다.

- 잔고 조회: `/uapi/domestic-stock/v1/trading/inquire-balance`, tr_id 실전 `TTTC8434R`, 모의 `VTTC8434R`
- 모의 접속 주소: `openapivts` 계열, 포트 29443 (실전 9443)
- 접근 토큰: 약 24시간 유효, 발급은 1분에 1번 정도로 제한
- 호출 제한: 모의 초당 1번 정도, 초과 시 `EGW00201`
- 잔고 조회는 여러 페이지로 나뉠 수 있으므로 연속 조회를 처리한다.

토큰은 호출 제한 때문에 재사용해야 하며, 키와 같은 수준으로 암호화해 저장한다.

## 보안과 개인정보

- 앱 키, 시크릿, 토큰은 암호화 저장한다. 화면에는 뒤 4자리만 보여 준다.
- AI 도구의 입력과 결과에 키, 토큰, 계좌번호 전체를 넣지 않는다. 계좌는 "모의 계좌 ****1234"처럼 표시한다.
- 보유 종목과 손익은 AI 브리핑에 필요하므로 도구 결과로 넘어간다. 구현 전에 대화 내용이 기기 밖으로 나가는 경로가 있는지 확인하고, 있으면 그 경로를 끄거나 사용자에게 알린다.
- 저장 파일은 계정 데이터 서버 동기화와 백업(`plugins/data_backup.py`, `data/backup.py`) 대상에서 빼거나, 잔고 기록을 내보내더라도 키와 토큰은 절대 포함하지 않는다.
- 증권사 응답과 오류를 로그에 그대로 남기지 않는다. `core/ai_worker.py`의 오류 로그를 포함해 키와 토큰이 찍히지 않는지 테스트한다.
- 키 삭제와 계좌 연결 해제 기능을 제공한다. 플러그인을 제거할 때 저장된 키도 함께 지울지 묻는다.

## 화면과 브리핑 동작

- **대시보드 위젯 [요청]:** 총 평가손익(금액, 수익률)과 보유 종목별 손익. 모의 계좌면 "모의" 표시를 항상 보여 준다. 마지막 갱신 시각을 함께 보여 주고, 실패하면 이전 값을 현재 값처럼 보이지 않게 표시한다.
- **손익 색상 [판단]:** 한국 관례에 따라 이익은 빨강, 손실은 파랑으로 하고, 색만으로 구분하지 않도록 +/- 기호를 함께 쓴다.
- **갱신 [판단]:** 위젯을 처음 볼 때, 새로고침 버튼을 누를 때, 화면이 보이는 동안 5분마다. 장이 닫혀 있으면 자동 갱신하지 않는다.
- **추천 차단 [판단]:** AI 안내문으로 추천을 금지하는 것에 더해, "뭘 살까", "지금 팔까", "오를까"처럼 명확한 추천·전망 질문은 코드에서 감지해 고정 문장으로 답한다. 감지는 `tests/unit`에서, 실제 모델의 답변은 `tests/llm_smoke`에서 시험한다. "삼성전자 어때?"처럼 애매한 질문은 보유 현황과 손익 사실만 답한다.
- **브리핑 [요청·판단]:** "내 주식 어때?", "오늘 손익 알려줘" 같은 말로 부른다. 숫자는 AI가 만들지 않고 도구가 계산해 만든 문장을 그대로 쓴다. 오늘 손익을 증권사 응답에서 믿을 만하게 얻을 수 없으면, 없는 값을 만들지 말고 전체 평가손익만 말한다.
- **미연결 상태:** 위젯과 대화에서 연결 방법을 안내한다. 발급 절차는 앱 안 안내와 링크로 제공한다.

## 완료 기준

- **1단계:** 모의 계좌로 연결, 조회, 브리핑, 위젯이 앱에서 동작한다. 키가 프롬프트, 대화 기록, 로그, 백업에 없다는 테스트가 있다. 명확한 추천 질문을 고정 문장으로 막는 테스트가 있다. 네트워크 실패와 토큰 만료 시 앱이 멈추지 않는다.
- **2단계:** AI 도구로 주문 API에 도달할 수 없다는 테스트가 있다. 확정을 누르기 전에는 주문 호출이 없고, 음성 경로로 확정되지 않으며, 한도 초과와 중복 클릭이 막힌다. 실제 모의 주문이 한 번 이상 성공한다.
- **3단계:** 모의 시세로 규칙 실행, 한도 초과, 오류 시 자동 정지, 중지 후 새 주문 없음, 재시작 시 꺼짐, 중복 실행 방지를 시험한다. AI 도구로 자동매매를 켤 수 없다는 테스트가 있다.
- **4·5단계:** 약관과 법 검토 결과가 문서로 남아 있고, 사람이 실제 계좌로 소액 시험을 했다.
